# הבוט של דוד (3 דירות נופש + תיווך לשותפים)

בוט וואטסאפ שעונה ללקוחות של דוד, מציע את הדירה המתאימה, מחשב מחיר, שולח תמונות, אוסף פרטים ורושם הזמנה. לקוח שלא מתאים לאף דירה (למשל זוג ושלושה ילדים, כשהדירה הכי גדולה מתאימה לזוג ושני ילדים) נאסף כ"ליד להעברה": הבוט אוסף את הפרטים ושולח אותם מסודרים למספר הפרטי של דוד. את ההעברה עושה דוד. (לבקשת דוד: בלי רשימת שותפים ובלי מעקב עמלות. אפשר להפעיל את שניהם ב-`referral` ב-config.) תקלות מגיעות לשותף שמטפל בהן, לא לדוד.

הבוט עונה גם בהודעות פרטיות באינסטגרם, ושיחה לעסק שלא נענתה הופכת להודעת וואטסאפ למתקשר.

**המצב:** הבוט בנוי ונבדק, 76 בדיקות עוברות, כולל בדיקת עומס של 150 לקוחות. נשאר רק להכניס את הנתונים של דוד ולחבר את החשבונות. `npm run check` מראה בדיוק מה חסר.

## מה הבוט עושה

**ללקוח**
- עונה תוך שניות, 24/7, בשפה שהלקוח כותב בה.
- מבין הודעות קוליות (תמלול עם Cloudflare Workers AI) ותמונות (למשל תמונה של תקלה בזמן שהייה).
- מתאים דירה לפי מבוגרים, ילדים ותינוקות, ומחשב מחיר מדויק לפי אמצע שבוע, סופ"ש, עונות, מינימום לילות ודמי ניקיון. המחיר מחושב בקוד, לא על ידי המודל.
- אם הדירה שביקש תפוסה, מציע דירה אחרת. אם הבעיה היא רק מינימום לילות, מציע להאריך.
- שולח תמונות של הדירה.
- רושם בקשת הזמנה. שני לקוחות לא יכולים לקבל את אותו לילה, גם אם הם מזמינים באותה שנייה.
- לקוח שקיבל מחיר ונעלם מקבל הודעת מעקב אחרי 3 שעות, ושוב אחרי 22 שעות.
- הודעות סביב השהייה: יום לפני ההגעה (קוד כניסה ו-Wi-Fi), ביום ההגעה, בבוקר העזיבה, בקשת ביקורת, והזמנה לחזור אחרי 120 יום.
- רשימת מבצעים בהסכמה בלבד. "הסר" מוריד מהרשימה.
- **אינסטגרם:** אותו בוט עונה על כל הודעה פרטית, כולל הודעות קוליות, תמונות, תגובות לסטורי, פוסט או ריל ששלחו, סטיקר ולחיצה על שאלה מוכנה (Ice breaker). גם אם Claude לא זמין, הלקוח מקבל תשובה ("נחזור אליך ממש בקרוב") והשותף מקבל התראה. באינסטגרם אין לנו טלפון, אז לפני הזמנה או העברת ליד הבוט מבקש מספר נייד. האישור חוזר לאינסטגרם, והתזכורות לפני ההגעה יוצאות בוואטסאפ.
- **שיחה שלא נענתה:** מספר **שלא שמור אצל דוד בטלפון** שהתקשר ולא נענה מקבל וואטסאפ ("ראינו שהתקשרת ולא הספקנו לענות"), וכשהוא עונה הבוט ממשיך איתו ויודע שהוא התקשר. מי ששמור (משפחה, ספקים, לקוחות קבועים) לא מקבל כלום. גם: לא יותר מהודעה אחת ל-24 שעות לאותו מספר, לא לנייח או למספר חסוי, לא למי שכתב "הסר", לא לשותפים, ולא למי שכבר מדבר עם הבוט. שיחה בלילה (22:00 עד 08:00) מקבלת את ההודעה ב-08:00.

**לדוד**
- התראה על כל הזמנה. מאשר עם `אושר B123`.
- "🔁 ליד חדש להעברה" למספר הפרטי: שם, טלפון, תאריכים, הרכב וגילאים, תקציב, אזור ובקשות, למה הלקוח לא מתאים לדירות שלו, וקישור לפתוח איתו שיחה.
- כל בוקר ב-07:00: מי נכנס, מי יוצא, מה מחכה לאישור. גם למנקה, אם הוגדר.
- בימי ראשון ורביעי ב-10:00: לילות פנויים בשבוע הקרוב, עם הצעה לשלוח מבצע.
- סיכום שבועי בראשון ב-09:00, כולל כמה שיחות שלא נענו קיבלו וואטסאפ וכמה מהם ענו.
- "📞 שיחה שלא נענתה מ-..." על כל שיחה שקיבלה הודעה, עם קישור לוואטסאפ של המתקשר (אפשר לכבות ב-`missedCall.notifyOwner`).
- **יומן גוגל:** כל הזמנה נכנסת ליומן של דוד ברגע שנרשמה ("⏳ ממתין לאישור"), הופכת ל-"✅" כשהוא מאשר, ונמחקת כשהוא מבטל או כשהבקשה פגה. כל מה שדוד מכניס ליומן בעצמו (משפחה, שיפוץ, הזמנה מטלפון) חוסם את הלילות האלה, והבוט לא יציע אותם. גם `חסום` ו-`שחרר` מופיעים ביומן. `יומן` בודק שהחיבור עובד.
- **סנכרון עם Airbnb ו-Booking:** לכל דירה יש קישור יומן (`.ics`) שמכניסים ב-Airbnb וב-Booking, כך שהזמנה מהבוט חוסמת את התאריכים גם שם. בכיוון השני הבוט קורא את היומנים שלהם כל 15 דקות.
- שומר אנשי קשר שלא יקבלו הודעה על שיחה שלא נענתה: דוד שולח לבוט איש קשר (או כמה ביחד) מהטלפון, או כותב `שמור 0541234567 יוסי`. `לא שמור 054...` מוחק, `שמורים` מראה כמה.
- **כשדוד עונה ללקוח בעצמו** (מהאפליקציה של וואטסאפ או של אינסטגרם), הבוט שותק באותה שיחה 12 שעות (`BUSINESS.handoff.pauseHours`), ולא שולח גם הודעות מעקב. הוא ממשיך לשמור מה הלקוח כותב, וכשהוא חוזר לענות הוא יודע מה דוד אמר. `הפעל 0541234567` מחזיר לבוט את השיחה מיד, `השתק 0541234567` משתיק אותה ידנית.
- **תשלום מקדמה:** כש-`bookingFlow: 'pay_to_confirm'` ויש `paymentLink`, הלקוח מקבל קישור וסכום מקדמה, ודוד מקבל התראה. כשהתשלום נכנס הוא כותב `שולם B123` וההזמנה מאושרת. לקוח שלא שילם מקבל תזכורת אחת עם הקישור אחרי 5 עד 20 שעות.
- **סיכום חודשי** ב-1 לחודש ב-09:00: פניות, בקשות הזמנה, הזמנות שאושרו, הכנסה, לידים ושיחות שלא נענו. אפשר גם לבקש עם `סיכום חודשי`.
- פקודות: `פנוי`, `חסום 2 2027-03-01 2027-03-04`, `חסימות`, `שחרר 5`, `מבצע: טקסט`, `היום`, `סיכום`. כל הודעה אחרת מחזירה את רשימת הפקודות.

**לנו (השותף שמטפל בתקלות)**
- כל תקלה נשלחת לשותף בוואטסאפ: מה קרה, איזה לקוח, ומה הלקוח קיבל. אותה תקלה נשלחת לכל היותר פעם ב-15 דקות.
- דוח פנימי בראשון ב-09:00: עלות Claude, צפי חודשי, עלות ממוצעת ללקוח, ותקלות. דוד לא רואה אותו.
- התראה אם העלות היומית עוברת את התקרה (`AGENCY.dailyBudgetUsd`).
- טוקן אינסטגרם מתחדש לבד כל יום שני ב-04:00 (בלי זה הוא פג אחרי 60 יום). אם החידוש נכשל, מגיעה התראה.
- `/health?token=...` מחזיר מצב, את השגיאה האחרונה ועלות ב-24 השעות האחרונות. אפשר לחבר אותו לשירות ניטור חינמי כמו UptimeRobot.

## לעלות לאוויר: צ'קליסט

### 1. נתונים מדוד
1. את התשובות מהשאלון (`bot-form/david/`) מכניסים ל-`src/config.js`. אפשר לבקש מ-Claude: "הנה התשובות של דוד, תכניס לקונפיג".
2. מגדירים `AGENCY.techPhone` עם המספר של השותף.
3. מריצים `npm run check` עד שאין חוסמים, ומחליפים ל-`DRAFT = false`.

### 2. Cloudflare (בתוכנית Workers Paid)
```bash
cd bots/david && npm install
```
```bash
npx wrangler d1 create david-bot
```
את ה-id שחוזר מכניסים ל-`wrangler.toml`, ואז:
```bash
npx wrangler d1 migrations apply david-bot --remote
```
אחר כך מגדירים את הסודות, כל אחד בפקודה נפרדת: `ANTHROPIC_API_KEY`, `WA_TOKEN`, `WA_PHONE_NUMBER_ID`, `WA_APP_SECRET`, `WA_VERIFY_TOKEN`, `HEALTH_TOKEN` (מחרוזת אקראית).
```bash
npx wrangler secret put ANTHROPIC_API_KEY
```
ולבסוף:
```bash
npx wrangler deploy
```

### 3. Meta (WhatsApp Cloud API)
1. מחברים את המספר של דוד. אפשר להמשיך להשתמש בו גם באפליקציה (coexistence).
2. Webhook: הכתובת היא `https://<worker>/webhook`, ה-Verify token הוא הערך של `WA_VERIFY_TOKEN`, ונרשמים ל-`messages`.
3. מאמתים את העסק (Business Verification) ומוסיפים אמצעי תשלום.
4. מאשרים תבניות (Utility, בעברית), ושמים את השמות ב-`TEMPLATES` ב-config. ב-`owner_alert` מגדירים גם `WA_NOTIFY_TEMPLATE`.

| שם מוצע | סוג | הטקסט |
|---|---|---|
| `owner_alert` | Utility | עדכון מהבוט: {{1}} |
| `stay_reminder` | Utility | היי {{1}}, תזכורת לקראת ההגעה מחר: {{2}} |
| `stay_welcome` | Utility | {{1}}, {{2}} צריך משהו? פשוט תכתוב כאן. |
| `stay_checkout` | Utility | בוקר טוב {{1}}. {{2}} |
| `stay_review` | Utility | {{1}}, {{2}} |
| `come_back` | Marketing | היי {{1}}, {{2}} |
| `offer` | Marketing | היי {{1}}, {{2}} להסרה כתבו "הסר" |

### 4. בדיקה לפני שבוע הניסיון
1. `curl "https://<worker>/health?token=..."` צריך להחזיר `ok: true`.
2. שולחים מהטלפון 10 עד 15 שיחות אמיתיות: זוג, משפחה גדולה (צריכה לעבור לתיווך), תאריכים תפוסים, הודעה קולית, תמונה, ו"הסר".
3. דוד שולח `עזרה` ומקבל את רשימת הפקודות.

### 5. אינסטגרם (לא חובה)
1. חשבון האינסטגרם של העסק צריך להיות מקצועי (Business או Creator). באפליקציה: הגדרות, פרטיות, הודעות, "כלים מחוברים", ומדליקים "Allow access to messages".
2. באפליקציה של Meta Developers (אותה אפליקציה של וואטסאפ) מוסיפים את המוצר Instagram ובוחרים "API setup with Instagram login".
3. מוסיפים את חשבון האינסטגרם של העסק (Add account) ומייצרים טוקן. הטוקן נשמר כסוד:
```bash
npx wrangler secret put IG_TOKEN
```
4. אם ל-Instagram יש App secret אחר מזה של וואטסאפ (רואים אותו במסך של Instagram באפליקציה), שומרים גם אותו:
```bash
npx wrangler secret put IG_APP_SECRET
```
5. Webhooks של Instagram: אותה כתובת (`https://<worker>/webhook`) ואותו Verify token, ונרשמים ל-`messages`.
6. **הרשאות:** כל עוד האפליקציה לא עברה App Review, היא עובדת רק עם חשבונות שיש להם תפקיד באפליקציה. ללקוח אחד או שניים מספיק להוסיף את החשבון שלו כ-Instagram Tester. כשיהיו הרבה לקוחות, צריך Business Verification ו-App Review להרשאה `instagram_business_manage_messages`, וזה לוקח כמה שבועות. כדאי להתחיל מוקדם.
7. בדיקה: שולחים הודעה לחשבון מחשבון אחר, והבוט עונה.

### 6. שיחה שלא נענתה
הבוט מקבל את השיחה בכתובת אחת, בלי קשר לספק:
`https://<worker>/missed-call?token=<MISSED_CALL_TOKEN>` עם מספר המתקשר בשדה `from` (או `From`, `caller`, `phone`, `number`).
```bash
npx wrangler secret put MISSED_CALL_TOKEN
```
(מחרוזת אקראית ארוכה.) אחר כך מאשרים ב-Meta את התבנית `missed_call` (Utility): `היי, ראינו שהתקשרת ל{{1}} ולא הספקנו לענות. אפשר לכתוב כאן במה אפשר לעזור, ונחזור אליך מיד. להסרה כתבו "הסר"`, ושמים את השם ב-`TEMPLATES.missed_call`.

ספק, לפי תקציב:
| ספק | איך | אמינות |
|---|---|---|
| **מספר וירטואלי** (Twilio, או ספק ישראלי כמו Voicenter) | קונים מספר. עדיף ישראלי, כדי שההעברה מהסלולרי לא תהיה שיחה לחו"ל. ב-Twilio: Voice webhook של המספר הוא `https://<worker>/missed-call?token=...` (POST). בטלפון של העסק מגדירים "העברה כשאין מענה" למספר הזה (אצל רוב המפעילים `**61*<מספר>#`, לבדוק מול המפעיל). הבוט עונה ל-Twilio עם צליל תפוס, כך שהמתקשר לא מחכה. | הכי אמין. מומלץ ללקוח משלם |
| **אפליקציה באנדרואיד** (MacroDroid) | טריגר "שיחה שלא נענתה", ופעולה "HTTP Request" ב-POST ל-`https://<worker>/missed-call?token=...&from={call_number}&source=android` | חינם. עובד רק כשהטלפון דלוק ומחובר, ולא באייפון. טוב לניסיון |
| **מרכזיה בענן** שהעסק כבר משתמש בה | מגדירים בה webhook לשיחה שלא נענתה לאותה כתובת. אם שם השדה אחר, מוסיפים `&from=` לפי מה שהמרכזיה תומכת | תלוי במרכזיה |

**רק מספרים שלא שמורים אצל דוד.** השרת לא רואה את אנשי הקשר בטלפון, אז מכניסים אותם לבוט פעם אחת, וכל איש קשר חדש דוד פשוט שולח לבוט:
1. **ייבוא כל אנשי הקשר (פעם אחת):** באייפון: iCloud.com, אנשי קשר, לבחור הכל, "ייצוא vCard". באנדרואיד: contacts.google.com, "ייצוא". ואז:
```bash
npm run contacts -- contacts.vcf
```
```bash
npx wrangler d1 execute david-bot --remote --file=contacts-import.sql
```
ומוחקים את שני הקבצים (מידע אישי, ו-`.gitignore` כבר מונע להעלות אותם).
2. **איש קשר חדש:** דוד משתף אותו לבוט בוואטסאפ (אפשר כמה ביחד), או כותב `שמור 0541234567 שם`.
3. **ב-MacroDroid** אפשר לבחור בטריגר רק מספרים שלא באנשי הקשר (Non-contact), ואז הסינון קורה בטלפון עצמו. ממרכזיה שיודעת אם המתקשר שמור, שולחים `&saved=1` והבוט ידלג.

`missedCall.enabled` כבר `true`, וכלום לא קורה עד שספק שולח לכתובת. ההגדרות שם: `cooldownHours`, `quietHours`, `notifyOwner`, `foreignNumbers`, `text`.

בדיקה:
```bash
curl -X POST "https://<worker>/missed-call?token=..." -H 'content-type: application/json' -d '{"from":"05XXXXXXXX"}'
```
עם המספר הנייד שלך. התשובה צריכה להיות `{"status":"sent"}` ותגיע הודעה. אם התשובה היא `skipped`, השדה `reason` אומר למה.

### 7. יומן גוגל וסנכרון עם Airbnb/Booking
**חשבון שירות בגוגל (פעם אחת, משמש את כל הלקוחות):**
1. ב-console.cloud.google.com יוצרים פרויקט, ומפעילים בו את Google Calendar API.
2. ב-IAM, Service Accounts, יוצרים חשבון שירות, ותחת Keys מוסיפים מפתח JSON ומורידים אותו.
3. שומרים אותו כסוד, ומדביקים את כל תוכן הקובץ כמו שהוא:
```bash
npx wrangler secret put GCAL_SA_JSON
```
4. ומוחקים את הקובץ מהמחשב.

**אצל דוד (5 דקות):**
1. ב-Google Calendar יוצרים יומן לכל דירה ("קו המים 1", "קו המים 2", "קו המים 3"). אפשר גם יומן אחד לכולן: אירוע שכתוב בו שם דירה חוסם רק אותה, ואירוע בלי שם דירה חוסם את כולן.
2. בהגדרות של כל יומן, "שיתוף עם אנשים ספציפיים", מוסיפים את המייל של חשבון השירות (`...@...iam.gserviceaccount.com`) עם ההרשאה **"ביצוע שינויים באירועים"**.
3. באותו מסך, "שילוב יומן", מעתיקים את "מזהה היומן" ושמים ב-`BUSINESS.calendar.perApartment` (או ב-`googleCalendarId` ליומן אחד).
4. דוד שולח לבוט `יומן`, וצריך לחזור ✅ על כל דירה.

**Airbnb ו-Booking:**
```bash
npx wrangler secret put CAL_FEED_TOKEN
```
(מחרוזת אקראית ארוכה.) הקישור לכל דירה הוא `https://<worker>/cal/<CAL_FEED_TOKEN>/apt1.ics` (וכך גם `apt2`, `apt3`). ב-Airbnb: לוח שנה, זמינות, "חיבור לאתר אחר", "ייבוא לוח שנה". ב-Booking: תעריפים וזמינות, סנכרון יומנים. בכיוון ההפוך, את קישור הייצוא של Airbnb ושל Booking שמים ב-`icalUrls` של הדירה ב-config.

**שימו לב:** Airbnb ו-Booking מושכים את הקישור לפי לוח הזמנים שלהם, בדרך כלל כל שעה עד כמה שעות, ולא מיד. אם מישהו מזמין באותן שעות גם בבוט וגם ב-Airbnb, יכולה לקרות הזמנה כפולה. כדאי להגיד את זה לדוד.

## כשדוד עונה בעצמו: חיבור ב-Meta
הבוט מזהה תשובה של דוד לפי "הד" של ההודעה שדוד כתב באפליקציה. צריך:
- וואטסאפ (coexistence): ב-webhook של האפליקציה מנויים גם ל-`smb_message_echoes`, בנוסף ל-`messages`.
- אינסטגרם: מנויים גם ל-`message_echoes`.
- להריץ את המיגרציה החדשה: `npx wrangler d1 migrations apply david-bot --remote` (0006).
- בבדיקה מקצה לקצה: דוד כותב ללקוח מהאפליקציה, הלקוח עונה, והבוט לא עונה. אחרי `הפעל` הוא חוזר לענות. אם ההד לא מגיע, הבוט פשוט ממשיך לענות כמו קודם, ואין נזק.

## מודולים (מה כל לקוח קנה)
ב-`BUSINESS.modules` אפשר לכבות כל מודול (`false`), ואז הבוט לא מציע, לא אומר ולא שולח שום דבר ממנו. המודולים: `instagram`, `missedCalls`, `calendar`, `voiceAndPhotos`, `followUps`, `stayMessages`, `offers`, `referrals`. מחירים ועלויות: `bots/MODULES.md`.
