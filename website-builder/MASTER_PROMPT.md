# MASTER_PROMPT — מערכת בניית אתרים

זהו פרומפט הבסיס למי שבונה אתר לקוח חדש במאגר הזה (Claude או בן אדם). המערכת בנויה כזיכרון מצטבר: כל אתר שנבנה משפר את הידע הזמין לאתר הבא.

## מבנה המאגר

```
/website-builder/
  /component-library/    ← הזיכרון המצטבר. תבניות שכבר עבדו, מבוססות ניתוח אתרים אמיתיים.
    hero-sections.md
    contact-forms.md
    galleries.md
    3d-effects.md
    testimonials.md
  /clients/
    /{שם-עסק}/            ← כל אתר לקוח, תיקייה נפרדת. index.html + נכסים (תמונות/לוגו)
  MASTER_PROMPT.md        ← הקובץ הזה
  build-log.md            ← יומן: מה עבד, מה לא, לכל בנייה
```

כל האתרים הם דפי HTML סטטיים בודדים (HTML+CSS+JS inline בקובץ אחד), בעברית, עם `dir="rtl"`, פרוסים ב-GitHub Pages ישירות מהמאגר (workflow ב-`.github/workflows/pages.yml`, נדחף ל-`main`).

## תהליך בניית אתר חדש

1. **קראו את ספריית הרכיבים לפני שמתחילים** — `component-library/*.md`. אל תמציאו מחדש תבנית Hero/יצירת-קשר/המלצות אם כבר יש תבנית שעובדת. סטו ממנה רק כשיש סיבה קונקרטית לפרופיל הלקוח הספציפי.
2. **צרו תיקייה חדשה** תחת `clients/{שם-עסק-לועזי-עם-מקפים}/` (למשל `clients/dani-electric/`). שם התיקייה תמיד תעתיק לטיני קצר של שם העסק, לא עברית ולא רווחים.
3. **בנו `index.html` יחיד** — HTML+CSS+JS inline, בלי build step, בלי תלויות npm. גופן: Heebo מ-Google Fonts (כמו בכל האתרים הקיימים) אלא אם יש סיבה לגופן אחר.
4. **מבנה עמוד סטנדרטי** (סטו רק אם הבריף דורש אחרת):
   - Hero עם h1 ממוקד-בעיה + CTA כפול (`tel:`/`wa.me`) — ראו `hero-sections.md`
   - סקציית "מה אנחנו נותנים" / שירותים
   - גלריה (אם יש תמונות עבודה איכותיות) — ראו `galleries.md`
   - המלצות עם ציטוטים אמיתיים מגוגל — ראו `testimonials.md`
   - סקציית פרטי קשר + כפתורי CTA חוזרים — ראו `contact-forms.md`
   - פס CTA sticky/צף בתחתית ב-mobile (אופציונלי, מומלץ)
5. **תמונות**: קבצים נפרדים בתיקיית הלקוח (`logo.png` וכו'), לא base64 מוטמע — ראו האזהרה ב-`galleries.md`.
6. **בדקו responsive** — כל האתרים הקיימים כוללים `@media` breakpoint סביב 600-680px למובייל. בדקו ידנית שהעמוד קריא במסך צר.
7. **עדכנו את `build-log.md`** בסוף הבנייה, לפי התבנית שבסוף הקובץ — מה עבד, מה לא, מה למדתם.
8. **אם גיליתם תבנית חדשה שעובדת טוב** (לא מכוסה בספריית הרכיבים הקיימת) — הוסיפו אותה לקובץ המתאים ב-`component-library/`, או צרו קובץ חדש אם זה קטגוריה חדשה לגמרי (למשל `pricing-tables.md`).

## עקרונות שנשמרים בכל האתרים הקיימים
- **בלי טפסים** — `tel:`/`wa.me` בלבד לכל CTA, ראו `contact-forms.md`.
- **ביקורות אמיתיות בלבד** — אף פעם לא מומצאות.
- **בלי אפקטים תלת-ממדיים כברירת מחדל** — ראו `3d-effects.md` למקרים שבהם כן רלוונטי.
- **קובץ HTML יחיד לכל אתר** (מלבד תמונות/לוגו) — פשטות פריסה, בלי build step.
- **עברית + RTL תמיד**, אלא אם הלקוח מבקש אחרת במפורש.

## פריסה
דחיפה ל-`main` מפעילה אוטומטית את `pages.yml` שמפרסם את כל תוכן המאגר ב-GitHub Pages. כתובת האתר הסופית: `https://{owner}.github.io/{repo}/website-builder/clients/{שם-עסק}/`.
