## שלב 3 — מיתוג ותוכן (30–60 דק׳)

1. **צבעים וגופנים** ב-`:root` ובקישור של Google Fonts. גופני תצוגה עבריים טובים: Bellefair, Frank Ruhl Libre, David Libre, Suez One, Noto Serif Hebrew.
2. **קופי** עם פרומפט 6.2 מ-`PREMIUM_PLAYBOOK.md`: כותרות של 2–5 מילים, וכל טענה עם פרט מוחשי.
3. **התמונה האמיתית לפתיח:**
   - **עדיף:** צילום של הלקוח עצמו (הדמיה, צילום רחפן, צילום מוצר).
   - **אחרת:** Unsplash, רק תמונות **שאינן Unsplash+**. מאתרים עם `WebFetch` על `unsplash.com/s/photos/<מילים>` (ה-API והחיפוש ב-curl חסומים בסנדבוקס, אבל `images.unsplash.com` פתוח).
   - מורידים שני גדלים לתיקיית הלקוח:
     ```bash
     curl -s "https://images.unsplash.com/photo-<ID>?w=1600&q=78&fm=jpg" -o hero-<x>.jpg
     curl -s "https://images.unsplash.com/photo-<ID>?w=900&q=74&fm=jpg"  -o hero-<x>-sm.jpg
     ```
   - **קרדיט בתמונה** (`figcaption`: "תמונת השראה · צילום: שם / Unsplash") עם קישור לעמוד התמונה.
   - תמונה לאורך (portrait) מתאימה לפריסה הזו: חצי מסך במחשב, מסך מלא במובייל. תמונה לרוחב צריכה `object-position` אחר.
   - **זהירות:** בתמונה של בניין אמיתי ומוכר, לא כותבים שהיא "הפרויקט של הלקוח". בקונספט: "תמונת השראה". באתר אמיתי: רק צילומים של הלקוח.

## שלב 4 — להחליף את האובייקט התלת-ממדי

**אופציה A — פרוצדורלי (כמו אבן, בלי קבצים):** בונים מגאומטריות בסיס (`CylinderGeometry`, `BoxGeometry`, `LatheGeometry` לבקבוקים/אגרטלים, `TorusGeometry` לטבעות) בלולאה. במגדל כל קומה היא `Group` של slab + glass, עם `rotation.y = i*0.022` ו-`scale` גלי (`1 + 0.085*sin(i*0.55)`).

**אופציה B — מודל אמיתי (GLB):**
```js
import { GLTFLoader } from 'three/addons/loaders/GLTFLoader.js';
new GLTFLoader().load('model.glb', (g) => {
  const m = g.scene; m.traverse(o => { if (o.isMesh){ o.castShadow = true; pickables.push(o); } });
  scene.add(m); A.ready = true;   // מעבירים את A.ready לכאן
});
```
מקורות ל-GLB: קובץ מהאדריכל (Revit/SketchUp → Blender → glTF), או Higgsfield `generate_3d` מתוך תמונה של הלקוח. יעד גודל: פחות מ-3MB.

**חשוב:** לשמור על `userData.<מזהה>` על כל חלק שאפשר לבחור, ועל ההדגשה כ-mesh נפרד. לא משכפלים חומרים.

## שלב 5 — תחנות מצלמה

```js
// [זווית ברדיאנים, מרחק, גובה מצלמה, גובה נקודת המבט, הסטה צידית]
const stops = { hero:[...], aerial:[...], facade:[...], top:[...], floors:[...] };
```
- **hero** מוסתר כרגע מאחורי התמונה האמיתית, אבל ממנו המצלמה יוצאת לפרק הראשון.
- **הסטה צידית** (האיבר החמישי): במחשב מזיזה את האובייקט הצידה כדי לפנות מקום לטקסט. במובייל תמיד 0.
- **למובייל תחנות נפרדות:** מרחק גדול יותר, ונקודת מבט נמוכה כדי שהאובייקט יעלה לחלק העליון של המסך.
- **בודקים שאין אובייקטים במסלול.** מסלול המצלמה הוא עיגול ברדיוס 9–36 סביב האובייקט, ושום גאומטריה לא נכנסת אליו.
- כוונון: משנים מספר אחד, מריצים בדיקה (שלב 7) ומסתכלים על צילום המסך של אותה סקציה.

## שלב 6 — האינטראקציה העסקית

הדפוס של אבן, שמתאים לכל תחום:
1. **מקור נתונים:** פונקציה אחת (`floorData`) שמחזירה פריטים עם שם, גודל, מחיר וסטטוס. באתר אמיתי מחליפים ב-JSON מהלקוח.
2. **בחירה משני מקורות:** לחיצה על האובייקט (raycast) **וגם** כפתורים (נגישות ומובייל). שניהם קוראים ל-`A.select(id)`.
3. **CTA עם הקשר:** `wa.me/<מספר>?text=` עם מה שנבחר. זה ההבדל בין "ליד" ל"ליד חם".
4. **סימון נתוני דמו:** כל עוד המספרים לא אמיתיים, כותבים "* להמחשה בלבד".

## איך נבנה "אבן" בפועל (הסדר המקורי, לתיעוד)

1. מחקר: Awwwards 2026 (סיפור שמונע מגלילה + רעיון אחד), מחירוני שוק ישראליים.

4. בדיקה ראשונה: ה-CDN נחסם בסנדבוקס, וה-fallback עבד (הוכחה שהוא תקין).
5. ניתוב ה-CDN דרך curl בבדיקה. נחשפו 4 באגים: בניינים במסלול המצלמה, class מתנגש (`.solid`), bloom חזק מדי, מילוי כפתור שדולף.
6. תיקון מובייל: תחנות מצלמה נפרדות ופאנל קומפקטי.
7. פרסום (PR #11).
8. בקשת לקוח: "תמונה אמיתית במקום המגדל המצויר" → פתיח עם צילום אמיתי (חצי מסך במחשב, מלא במובייל), והתלת-ממד נשאר לסיפור ולבחירת הקומה. **לקח:** תמונה אמיתית בפתיח ותלת-ממד לאינטראקציה זה שילוב חזק יותר משניהם לבד.
